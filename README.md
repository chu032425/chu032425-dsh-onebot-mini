# dsh-onebot-mini

[English](README.en.md) | 中文

把 DeepSeek Harness 接到 **OneBot 11**（NapCat / Lagrange / LLOneBot）的最小通道插件：

- QQ 私聊与群聊消息 → dsh 会话（一个 chat 一个持久会话，重启自动续）；
- 模型回复 → 通过 OneBot 接口发回原聊天；
- `onebot_call` 工具：模型可直接调 OneBot 动作（发图、发文件、群管理、戳一戳、撤回、QQ 空间…），
  按 [NapCat 接口文档](https://napcat.apifox.cn/) 收录 **118 个动作 / 9 个分组**，可在左侧「工具」菜单按分组/动作开关；
- **收到的媒体可读取**：用户发来的图片/语音/视频/文件自动下载到工作区下的 `onebot-mini-cache/QQ/<QQ号或群号>/`
  （与 QQ 空间图片缓存同一处，统一在「缓存」页可查、可清理），消息里给出本机路径（图片用 `read_image` 看，文件用 `read`/`bash` 读，语音自动转写：取网关 QQ 自带结果）；`deleteInboundMedia` 默认在解析完这一轮后删除源文件，和「发送后删除源文件」一致；
- **配置页**：改连接参数并立即重连；
- **好友与群组页**：好友可展开看在线状态，群可展开看成员列表；
- **访问控制页**：私聊/群聊的白名单与黑名单，用下拉菜单挑选；
- **空间页**：查询 QQ 空间资料、我的说说与好友动态；
- **个人资料页**：默认显示机器人自己的详细资料，可下拉切换任意好友；
- **日志页**：实时看 WebSocket 连接 / 断开 / 发送 / 接收；
- **缓存页**：查看插件产生的所有文件（设置、日志、缓存文件）及占用，并可手动清理；
- **提示词页**：查看/修改注入到 QQ 会话的频道提示词，支持恢复默认。

零运行时依赖（WebSocket 服务端为手写实现），可从 git、tarball 或本地 `link:` 安装。

> **所有动作都走同一条 WebSocket 连接**，不使用 HTTP。
> NapCat 文档里写的是 `/send_msg` 这类 HTTP 路由，那只是接口参考；
> 本插件把动作名 + 参数装进 `{"action":…,"params":…,"echo":…}` 帧，
> 通过已建立的 WebSocket 发出，再用 `echo` 匹配响应。
> 仓库里唯一的 `node:http` 用途是反向模式下**监听**网关拨入（升级为 WebSocket），
> 不是 HTTP 客户端。

## 安装

```sh
dsh plugin --profile web add https://github.com/<you>/dsh-onebot-mini
```

或在 Web 界面 **Plugins → Add plugin** 里填仓库地址。安装后重启 `dsh web`。

**NapCat 侧配置**（二选一）：

- **反向（推荐）**：NapCat → 网络设置 → 新建「WebSocket 客户端」，上报地址
  `ws://<dsh 所在机器 IP>:8643`（端口填你配置里的 `port`），token 填本插件的 `accessToken`。
- **正向**：NapCat 启用「WebSocket 服务端」（默认 `3001`），本插件 `url` 填
  `ws://<NapCat 所在机器 IP>:3001`。

两侧 token 必须一致；消息上报格式建议选「数组」。

## 机器人账号（自动回填）

`botQQ` 不用手填，设置页里它是**只读展示**：连上网关后，插件从事件帧里的 `self_id`
读到机器人账号，**立刻写回配置文件**，字段里显示这个值并提示「当前连接识别到：<QQ号>」。

只有极少数非标准网关不在事件里带 `self_id`，才需要手填。

## 首次配置

左侧栏点 **OneBot** 图标，面板左侧是选项卡、右侧是详情页：

- **设置**：连接、访问控制、会话、诊断四组；
- **日志**：实时 WebSocket 收发。

（配置不放在 Plugins 页里，本插件的侧栏面板就是唯一操作入口。）最小可用配置：

1. `连接模式`：反向（默认）；
2. `监听地址`：**NapCat 与本插件不在同一网络命名空间时必须填 `0.0.0.0`**——
   填 `127.0.0.1` 只监听回环，NapCat 连容器 IP 会得到 `ECONNREFUSED`；
   同机同命名空间才可用 `127.0.0.1`；
3. `访问令牌`：与 NapCat 一致（**反向模式留空会拒绝启动**）；
4. 保存 → 提示「已保存，网关已重连」。

配置存在 `<DSH_HOME>/profiles/<profile>/onebot-mini.json`，不是 Loader 的
`config:` 块——所以**通过配置页保存**只重建 WebSocket 连接，不重启插件，进行中的会话不受影响。

注意：该文件在插件挂载时读取一次。**手改这个文件需要重启 `dsh web` 才生效**；
日常改配置请用配置页。

## 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `mode` | `reverse` | `reverse`=网关拨入；`forward`=插件拨出 |
| `host` / `port` | `127.0.0.1` / `8643` | 反向监听；跨机部署改 `0.0.0.0` |
| `url` | `ws://127.0.0.1:3001` | 正向目标 |
| `accessToken` | 空 | 反向必填；正向作为 `Authorization: Bearer`。设置页为密码型输入框，带**眼睛按钮**可切换明文/隐藏；文件里是明文 |
| `botQQ` | 空 | 机器人账号；**连接后自动识别并回填**，一般无需手填 |
| `requireMention` | `true` | 群聊需 @ 机器人才响应（`botQQ` 未知时 fail-closed） |
| `allowFrom` / `allowGroups` | `[]` | 白名单；空=不限制。在左侧「访问控制」菜单里用下拉选择 |
| `denyFrom` / `denyGroups` | `[]` | 黑名单；**优先级高于白名单**，命中的会话一律拒绝 |
| `workspacePath` | **必填** | 会话工作区；设置页从现有工作区下拉选择，被删除时自动重建 |
| `agentPreset` | 空 | 会话使用的 agent 预设；设置页从现有预设下拉选择，留空=部署默认，被删除/损坏时自动回退默认 |
| `agentModel` | 空 | 会话使用的模型；设置页从部署的 provider/model 目录下拉选择，留空=部署默认 |
| `sessionPermission` | **必填** | 会话权限预设（沙箱+审批），设置页下拉选择，新建会话时应用 |
| `onebotToolEnabled` | `true` | 是否给模型注册 `onebot_call` 工具；关=模型完全看不到它 |
| `onebotToolDisabled` | `[]` | 被禁用的 OneBot 动作名单（左侧「工具」菜单按分组/动作勾选，未勾选=禁用；未知动作会被忽略） |
| `senderPrefix` | `true` | 群消息加 `[HH:MM 昵称(QQ)]` 前缀 |
| `sessionPrefix` | `onebot` | 会话 ID 前缀；小写字母开头，只含小写字母/数字/连字符 |
| `titleEqualsId` | `true` | 会话标题钉成会话 ID（见下） |
| `logCapacity` | `500` | 日志保留条数 |
| `logMessagePreview` | `true` | 日志是否记消息正文前缀 |
| `sendTimeoutMs` | `30000` | 动作超时 |
| `inboundMedia` | `true` | 是否下载用户发来的图片/语音/视频/文件到工作区并交给模型读取；关=只保留 `[图片]` 类占位符 |
| `inboundMediaMaxMb` | `20` | 单个接收媒体的大小上限（MB），超过即不下载、只保留占位符 |
| `deleteInboundMedia` | `true` | 收到的媒体在模型处理完这条消息的那一轮对话结束后删除本机源文件（与「发送后删除源文件」对应）；关=留在缓存目录手动清理 |
| `sttEnabled` | `true` | 语音自动转文字：调用网关 QQ 自带的转写（NapCat `fetch_ptt_text`），附在 `[语音: …]` 后；关=语音只给文件路径 |
| `deleteSentMedia` | `true` | 发出媒体后删除用过的本机源文件 |

## 收到的媒体

用户发来的图片、语音、视频、文件不再只是 `[图片]` 这样的占位符：

- 图片、语音、视频会从网关给的 URL（或经 `get_file` 拿到的下载地址）下载到
  会话工作区下的 `onebot-mini-cache/QQ/<QQ号或群号>/`（与 QQ 空间图片缓存同一处，
  统一在「缓存」页展示与清理），消息文本里给出本机绝对路径：
  `[图片: /workspace/QQ/onebot-mini-cache/QQ/2000001/…-image.png]`；
- 模型据此用自带工具读取：图片走 `read_image`，文本/表格/压缩包走 `read` 或 `bash`；
- 语音向网关索取 QQ 自带的语音转文字结果：调用 NapCat 的 `fetch_ptt_text` action
  （`{ message_id }`，返回 `data.text`），成功就附在 `[语音: …]（转写：…）` 后面。这只是
  网关的一个动作，**不依赖任何其它插件、npm 包或本机程序**；网关不支持或没返回时就只给路径；
- 文件给 `[文件: 名称, /绝对路径]`；
- 小程序/分享卡片等富消息（`json`/`xml` 段，以及音乐/位置/名片等）以 `[卡片: 标题]` 之类占位交给模型，不再因为无法解析而被当成空消息丢弃；
- **绝不静默丢消息**：没见过的段类型（如 `markdown` 之类）不会硬塞给模型，而是直接回复「暂时不能处理这种消息（类型）」；空消息、只有回复标记的消息也回一句「暂时不能处理这条消息」。群聊仍需 @ 机器人才响应，黑名单会话仍保持静默（这是访问控制，不是丢弃）；
- 下载失败、超过 `inboundMediaMaxMb`、或关闭了 `inboundMedia` 时，退回不带路径的占位符，
  模型会如实说明没收到，而不是编造内容；
- 图片扩展名按**魔数**判定（PNG/JPEG/GIF/WebP），避免「PNG 存成 .jpg 导致 read_image 类型不符」；
- **解析后删除源文件**：`deleteInboundMedia` 默认开启时，这条消息所在的一轮对话结束后就把本机文件删掉（与「发送后删除源文件」对应；若本轮回复要把这张图再发回去，会等发送完成后再删）。关掉后文件留在缓存目录，按「缓存」页对应 `QQ/<号>` 项手动清空即可（无定时任务）。

## 会话工作区

`workspacePath` 是**必填**项，设置页里是一个下拉框，列出当前部署已有的工作区
（`标题 — 路径`），聊天会话都创建在选中的工作区下，侧栏里能按工作区分组看到。

- 工作区注册被删除、或目录本身不存在时，收到下一条消息会**自动重建**：
  先建目录，再注册工作区，然后把会话挂进去；
- 下拉框里若出现「工作区已删除，连接时会自动重建」的选项，说明配置里记的路径
  当前不在注册表中，连接后会自动修复。

## 会话预设 / 权限 / 模式

这三项都在设置页「会话」组，只作用于**新建**的 QQ 会话（已有会话保持原状，
避免覆盖你在 Web 界面里手动改过的设置）：

| 项 | 作用 | 缺省行为 |
|---|---|---|
| `agentPreset` | 该会话挂载哪套 agent 预设（决定工具、技能、提示词） | 留空用部署默认；选中的预设被删除或损坏时回退默认 |
| `agentModel` | 该会话跑在哪个 provider/model 上 | 留空用部署默认；配置的模型不在目录里时回退默认 |
| `sessionPermission`（必填） | 会话权限预设，把沙箱级别与审批策略打包（如 `workspace-write` / `danger-full-access` / `read-only`） | 无 |

三项都调用宿主服务下发（`agentPresets.mount` / `permissionPresets.set` /
`planMode.set`），预设是**真的加载**其插件组合，不只是记在会话头上。

## onebot_call 工具开关

左侧边栏的 **工具** 菜单里，可按 **分组 + 单个动作** 勾选模型能调用的 OneBot
动作（发送消息、媒体与文件、群管理、账号与查询、请求处理）。每一项都是一个列表行：
勾选框 + **中文说明** + 动作 id（如 `禁言群成员 / set_group_ban`）。规则：

- 默认全部启用；关闭总开关，或把某组 / 某动作取消勾选，对应动作就被拒绝
  （工具返回 `disabled in the OneBot-Mini settings`，不会真正发到网关）；
- 关掉**总开关**、或一个动作都不剩时，工具**不注册**，模型上下文里看不到它；
- 只影响 `onebot_call` 工具本身；普通文字回复的自动转发**始终生效**，不受影响；
- 改动只对**新建**的会话生效，已有会话保持创建时的工具集。

存储上记录的是「被禁用的动作」列表，所以以后版本新增的动作对老配置默认是启用的。

## 会话 ID 与标题

会话 ID = `<sessionPrefix>-private-<QQ号>` / `<sessionPrefix>-group-<群号>`，
默认前缀 `onebot`，可在设置页的「会话」组改：

- **必须以小写字母开头**，只允许小写字母、数字、连字符；不合规的值会被拒绝并回退默认值
  （配置页会显示具体原因，不会静默改写）；
- **改前缀不会迁移已有会话**：新前缀只影响之后新建的会话，旧会话仍以旧 ID 留在侧栏。
  想让某个 chat 换到新前缀，需要先删掉旧会话再发一条新消息。

`titleEqualsId: true` 时，创建会话后立刻把标题钉成同一个字符串（走宿主的
`sessionTitle.rename`），所以侧栏里会话名就是 ID，后续新消息不会触发自动改名。
关掉这项则交给宿主的默认标题逻辑。

## 访问控制页

左侧「访问控制」菜单管四个名单，全部用**下拉菜单**从当前机器人的好友/群组里挑选，
选中的条目以可移除的标签展示，也可手动输入号码（网关离线时用）：

| 名单 | 作用 |
|---|---|
| 私聊白名单 `allowFrom` | 只接收名单内好友；空=全部放行 |
| 私聊黑名单 `denyFrom` | 名单内好友一律拒绝 |
| 群聊白名单 `allowGroups` | 只接收名单内群；空=全部放行 |
| 群聊黑名单 `denyGroups` | 名单内群一律拒绝 |

判定顺序是**先黑后白**：黑名单命中直接拒绝，然后白名单非空时只放行名单内的会话。
设置页里只留「群聊需 @ 才回复」一个开关，四个名单都搬到这个独立菜单。

## 好友与群组页

左侧栏面板的 **好友与群组** 菜单以列表形式展示当前机器人账号的好友和群：

- 好友：优先显示备注，没有备注显示昵称；每行都带 QQ 号，点开可看**状态/详情**
  （昵称、备注、性别、年龄、等级、QID、在线状态）；
- 群组：显示群名、群号与成员数（`成员 5`），点开可展开**成员列表**
  （群名片优先，其次昵称，带群主/管理员/成员标识）；
- 数据实时从网关读取（`get_friend_list` / `get_group_list`），点「刷新」重新拉取；
- 网关未连接时页面提示未连接；某个查询不被网关支持时，只有那一段显示不可用，
  另一段照常显示。

这是只读页面，不会改动机器人账号上的任何好友或群设置。

> 在线状态读的是 NapCat 的扩展动作 `nc_get_user_status`（`status: 10` = 在线）。
> 换用别的网关时若没有这个动作，页面显示「未知（网关不提供）」，而不是假装离线。

## 工具目录覆盖范围

`onebot_call` 的动作目录按 NapCat 官方接口文档整理，共 **118 个动作 / 9 个分组**：
发送消息、媒体与文件、群管理、查询与信息、互动与消息操作、请求处理、账号资料、
QQ 空间、群相册。

以下动作**故意不收**，因为交给模型会泄密或弄坏运行中的机器人：

| 类别 | 例子 |
|---|---|
| 凭据与密钥 | `get_credentials`、`get_csrf_token`、`get_cookies`、`get_rkey`、`get_clientkey` |
| 自毁操作 | `set_restart`、`bot_exit`、`clean_cache`、`clean_stream_temp_file` |
| 原始协议 | `send_packet`、`nc_get_packet_status`、流式上传/下载 |

另有一批偏门或平台相关的也没收（闪传/在线文件、自定义表情、群打卡、频道、Ark 卡片、
内联键盘、仅 Windows 的 `ocr_image`、需配置 AI 角色的 AI 语音）。

工具页顶部有**搜索框**，可按动作名或中文说明过滤；未勾选的动作即使被模型调用也会被拒。

> 文档里的 HTTP 路由（如 `/send_msg`）只是动作名的参考，插件从不发 HTTP 请求：
> 每个动作都作为一帧 WebSocket 消息发出，日志页的「发送/接收」记录的就是这些帧，
> 两者用同一个 `echo` 配对。

模型看到的系统提示里会自动列出**当前已启用**的动作（分组 + 动作名 + 中文说明），
所以关掉某个动作后模型根本不会再尝试它。

## 个人资料页

左侧「个人资料」菜单默认展示**当前机器人**的资料，也可以用下拉框（列表来自真实好友）
切换到任意好友：

| 字段 | 来源 |
|---|---|
| QQ 号 / UID / QID / 昵称 / 备注 | `get_stranger_info`（机器人自己还会读 `get_login_info`） |
| 个性签名 | `long_nick` |
| 性别 / 年龄 / QQ 等级 / 登录天数 / 注册时间 | `get_stranger_info` |
| VIP / 年费 VIP / VIP 等级 | `is_vip` / `is_years_vip` / `vip_level` |
| 在线状态 | `nc_get_user_status`（`status: 10` = 在线） |
| 获赞 | `get_profile_like` |

页面是**只读**的。网关缺少某个动作或字段时，对应项直接不显示（在线状态显示「未知」），
不会让整页失败。

## 空间页

左侧「空间」菜单展示当前机器人账号的 QQ 空间内容，**只读**：

| 区块 | 数据来源 | 说明 |
|---|---|---|
| 空间资料 | `get_qzone_profile` | 空间名称与说明 |
| 我的说说 | `get_qzone_msg_list` | 正文、时间、评论数、赞数、图片数、是否私密 |
| 好友动态 | `get_qzone_feeds` | 同上，额外显示作者 QQ 号 |

网关返回的两种格式（SnowLuma 的 `{total, msglist}` 与原生 H5 数组）都会被归一成同一组字段；
某个区块不被网关支持时只有那一段显示原因，其余照常显示。

页面顶部两种选法：**下拉选好友**（选项来自真实好友列表）或**手动填 QQ 号**（不是好友也能看），
默认读机器人自己的空间。都走 `target_uin`。实测好友空间能正常返回资料与说说列表。

一次只取 **10 条**（`num` 上限 20），因为每条说说可能带图，取太多会让面板卡顿；
要翻更多内容用 `onebot_call` 的 `get_qzone_msg_list` 配合 `pos` 分页。

### 图片与本地缓存

说说里的图片会显示成缩略图，点开看原图。图片**下载一次就缓存在本地**，之后不再重复请求。

- 缓存位置：`<workspacePath>/onebot-mini-cache/QQ/<QQ号>/<hash>.<ext>`
  —— 用 QQ 号分文件夹，不同账号互不影响；与收到的媒体缓存在同一棵树下（见「缓存目录约定」）；
- **下载前先判大小**：先发 `HEAD` 看 `Content-Length`，超过 `imageCacheMaxKb`（默认 1024 KB）
  就直接放弃，不读正文；没有 `Content-Length` 时边读边计数，超了立即中断；
- **总量有上限**：`imageCacheTotalMb`（默认 100 MB），每次写入后按最旧优先清理，直到不超预算；
- **超过缓存上限但不算巨大**的图**不写磁盘，仍会流式显示**一次：
  面板上看得见，只是下次还会再下载。超过「空间单张图片显示上限」的图、或拉取
  失败的图显示「图片加载失败」占位，而不是破图图标；
- 同一张图并发请求只会下载一次（in-flight 去重）；
- 只允许 `*.qq.com` / `*.qpic.cn` / `*.qlogo.cn` / `*.gtimg.com` / `*.myqcloud.com` 的图片地址，
  防止帖子里的恶意 URL 被用来探测内网（SSRF）；
- 图片经 `/onebot-mini/api/image?qq=<号>&url=<地址>` 代理返回，所以浏览器不需要带 QQ 的登录态。

三个上限都在设置页的**「空间」组**里可调：

| 设置项 | 默认 | 作用 |
|---|---|---|
| 单张图片缓存上限（KB） | 1024 | 超过就不写磁盘 |
| 图片缓存总量上限（MB） | 100 | 超出后按最旧优先清理 |
| 空间单张图片显示上限（MB） | 32 | 超过就完全不显示（避免卡死/占内存） |

### 看不了某个好友的空间？

如果页面提示「看不了这个空间：对方设置了访问权限」，这不是插件的问题：
腾讯对受限空间返回 `-4009` / `-10031`，插件把它转成了可读的说明。
同一个接口对公开的空间照常返回内容（可以用另一个好友验证）。

发表说说、评论、点赞这类**写操作**不放在这个页面上，避免误点发出去；
模型可以通过 `onebot_call` 调用（「QQ 空间」分组的 14 个动作）。

## 回复行为

只有一个开关：**私聊：回答中允许自动插话**（默认开）。

| 情况 | 行为 |
|---|---|
| 模型**空闲** | 消息立即作为新回合投递 |
| 模型**正在回答**（私聊）且开关开 | **立即插话**（`steer`），在下一个 step 边界插入 |
| 模型**正在回答**（私聊）且开关关 | 排队为下一回合 |
| 模型**正在回答**（群聊） | 排队为下一回合（群聊从不插话，多人共享会话不能混） |

没有防抖窗口：每条消息到达就处理，不做合并等待。

`steer` 只在下一个 step 边界插入，不撤回已生成内容；想立刻中止需用 `cancel()`。

群消息推荐开启「发言人前缀」，让模型能分辨是谁在群里说话。

## 提示词页

左侧「提示词」菜单展示并编辑**所有模型可见的提示词**。页面由一份**提示词注册表**驱动，
以后代码里新增一处提示词，只要在注册表登记一条，就会自动出现在这个页面上、自动持久化。

当前收录五处：

| 提示词 | 作用 |
|---|---|
| 频道提示词 | 注入到每个 QQ 会话 system prompt 的频道说明 |
| 收到的媒体提示词 | 告诉模型收到的图片/语音/视频/文件已存到本机、如何用 `read_image`/`read` 读取（关闭接收媒体时不注入） |
| onebot_call 工具描述 | 模型决定是否调 `onebot_call` 时读到的说明 |
| onebot_send_media 工具描述 | 模型决定是否发媒体时读到的说明 |
| 插话判定提示词 | 私聊里新消息该「插话」还是「排队」时，判定器读到的说明 |

频道提示词的占位符：

| 占位符 | 展开为 |
|---|---|
| `{senderPrefix}` | 「群消息带发言人前缀」的说明（关闭时为空） |
| `{media}` | 媒体发送说明（工具关闭时为空） |
| `{tools}` | 本插件工具清单（`onebot_call` / `onebot_send_media` / `onebot_list_files`）与「QQ 相关操作只能用这些工具」的硬规则（工具关闭时为空） |
| `{inbound}` | 收到的媒体说明（`inboundMedia` 关闭时为空） |
| `{actions}` | 当前**已启用**的动作列表（工具关闭时换成「工具已关闭」提示） |

- 其它文字都可以自由改，改完点「保存提示词」；
- 「恢复默认」一键还原；
- 留空保存也会回到默认（避免误删导致模型失去频道说明）；
- 占位符会按当前配置**实时展开**，所以改了动作开关不用再改提示词；
- `onebot_call` 描述里的 `{enabledNote}` 会在工具启用时展开成「只接受已启用动作」那句，关闭时为空；
- 每一项都有自己的「恢复默认」，保存时只提交改动过的项。

## 缓存目录约定（新增缓存必须遵守）

**所有会话缓存都放在配置的会话工作区下，按下面的路径写，不要再另选位置：**

```
{workspacePath}/onebot-mini-cache/QQ/{QQ号或群号}/<缓存文件>
```

- `QQ空间图片`：`{workspacePath}/onebot-mini-cache/QQ/<QQ号>/<hash>.<ext>`
- `收到的媒体`（图片/语音/视频/文件）：`{workspacePath}/onebot-mini-cache/QQ/<QQ号或群号>/…`
  （`deleteInboundMedia` 开启时，解析完该轮后即删除，不长期占用这里的空间）
- 没有对应 QQ 号/群号的缓存：`{workspacePath}/onebot-mini-cache/<自定义名称>/`
- 例（工作区 `/workspace/QQ`）：
  `/workspace/QQ/onebot-mini-cache/QQ/2000001/`、`/workspace/QQ/onebot-mini-cache/QQ/2000003/`

理由：QQ 空间按账号抓取、收发消息都带 QQ 号/群号，用 `QQ/{号}` 二级目录即可同时覆盖空间与聊天媒体；
统一到 `onebot-mini-cache/` 一棵树下，「缓存」页一处可视、一处清理；放在工作区内，模型用
`read_image`/`read` 也能直接读。

- 设置文件 `onebot-mini.json` 与日志 `onebot-mini.log.jsonl` 仍在 profile 目录（`~/.dsh/profiles/<profile>/`），
  它们不是缓存，不适用上面的约定；
- 若配置里没有 `workspacePath`（正常不会），缓存退回 `~/.dsh/profiles/<profile>/onebot-mini-cache/` 以保可用。

> 代码里这条约定集中实现在 `cachepaths.js`（`cacheBase` / `accountDir`），**新增任何写缓存的代码都请复用它**，
> 不要自己拼路径，避免以后又散落各处。

## 缓存页

左侧「缓存」菜单把插件写到磁盘上的东西集中展示（数据实时从磁盘统计）。缓存**不限于图片**——
目录里是什么就列什么，按扩展名分类：

| 区块 | 内容 |
|---|---|
| 设置文件 | `onebot-mini.json` 的路径与大小（**不提供删除**，删了会丢配置） |
| 日志文件 | `onebot-mini.log.jsonl` 的大小与行数，可「清空日志」 |
| 缓存文件 | 按 QQ 号分组，显示每个账号的大小与文件数；展开后每个文件都标注**类型**（图片 / 音频 / 视频 / 文件），可按账号或整体清空 |

顶部显示合计占用与缓存根目录。所有清理都是**手动、需二次确认**的；没有定时任务，
不会自己删东西。

左侧栏 **OneBot** 面板，显示 7 类事件：

| 类型 | 内容 |
|---|---|
| 连接 / 断开 / 重连 | 模式、地址、断开原因、第几次重连与退避 |
| 发送 / 接收 | action 名、参数、retcode、耗时 |

## 出站行为

模型一轮回复里的所有 `text` 块会被缓冲，在 `turn/end` 时合并成**一条**消息发出——
多步回合不会刷屏。`reasoning` 与 `tool-call` 块不会发出去。
回合出错且没有文本时，发一条 `⚠️ 本轮出错：…` 提示。

**自动回复只发文字。** 图片 / 语音 / 视频 / 文件要走 `onebot_send_media` 工具（模型主动调用）：

| 参数 | 说明 |
|---|---|
| `kind` | `image` / `record` / `video` / `file` |
| `path` | DSH 本机文件路径；插件读取后**内联为 base64**，NapCat 不需要访问本机文件 |
| `url` | 网关能访问到的 http(s) 地址 |
| `base64` | 原始 base64（不带 `data:` 前缀） |
| `chatType` / `chatId` | 省略则用当前会话 |

单次上限 20 MB。同样有一条 `POST /onebot-mini/api/send-media` 接口供页面/脚本调用。

### 让回复本身带媒体

模型在回复文字里写标记，插件会在 `turn/end` 时把它们替换成真正的消息段，
和文字**合并成一条消息**发出（图文一起，不会分成两条）：

```
给你看这张图 [[image:/tmp/shot.png]] 好看吗
[[record:/tmp/a.wav]]
[[video:/tmp/a.mp4]]
[[file:/tmp/report.pdf]]
```

- 标记里的路径可以是 **DSH 本机的绝对路径**（插件读出字节并内联 base64），
  也可以是 **http(s) URL**；
- 文件不存在或超过 20 MB 时，这条媒体会退化成一句
  `[image failed: …]` 文字，**不影响其余内容发出**；
- 四种标记：`image` / `record` / `video` / `file`。

### 发送后删除源文件

设置页「媒体」组有一个开关 **「发送后删除源文件」**（默认开）：

- 通过 `[[image:/path]]` 标记、或 `onebot_send_media` / `send-media` 接口发送**本地路径**的媒体时，
  **网关确认发送成功后**才删除该源文件；
- 用 URL 或 base64 发送的没有源文件，不受影响；
- 删除有安全护栏：只删普通文件，且只允许 `/tmp`、`/workspace`、DSH 数据目录下的路径；
  目录、根路径、其它位置一律拒绝（日志里会记「kept: 原因」）；
- 关掉这个开关后就完全保留源文件。

## 已知限制

- **不下载媒体**：图片 / 语音 / 视频 / 文件只以 `[图片]` `[语音]` `[视频]` `[文件]`
  占位出现在文本里，模型看不到内容。要让模型看图需另加媒体管线。
- **不做 Markdown 转换**：提示词要求模型输出纯文本，但插件不做格式剥离。
- **无斜杠命令**：没有 `/new` `/stop` 之类，重启会话请用 dsh 界面。
- **无权限分档**：所有通过门禁的用户都用同一个 agent 预设。

## 卸载

```sh
dsh plugin --profile web remove dsh-onebot-mini
```

配置与日志文件保留在 `<DSH_HOME>/profiles/<profile>/onebot-mini.json`，需要时手动删。
